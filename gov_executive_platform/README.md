# المنصة التنفيذية الحكومية (Gov Executive Platform)

منصة تنفيذية حكومية حديثة لإدارة ومتابعة الخطة الاستراتيجية ومشاريع الوزارة على مستوى الرؤساء
التنفيذيين، بأسلوب متابعة مهام يشبه Jira / Trello (لوحات Kanban لكل مشروع)، مبنية بـ Flutter
وواجهة عربية أولى بالكامل (RTL) ومتجاوبة مع مختلف الأجهزة، ومربوطة بالكامل بخدمة **Firebase**
(مصادقة حقيقية، قاعدة بيانات سحابية، دوال خلفية، واستضافة).

## الأدوار والصلاحيات

| الدور | الصلاحيات |
| --- | --- |
| مسؤول نظام (System Admin) | كامل الصلاحيات: إدارة المستخدمين، جميع الإدارات والمشاريع، سجل التدقيق، اعتماد كل الطلبات |
| مستخدم تنفيذي (Executive Viewer) | عرض جميع الإدارات والتقارير ومركز القرارات (بدون تعديل)، مع اعتماد "القرارات التنفيذية" العامة فقط |
| مدير إدارة (Department Manager) | تعديل مشاريع إدارته فقط، إدخال التحديثات اليومية، طلب إضافة مشاريع وتعديل مواعيد نهائية |
| ضابط مشروع (Project Officer) | تحديث المهام اليومية على لوحة المشروع (الحالة ونسبة الإنجاز) ضمن إدارته |

## بوابات الموافقة (Approval Gates)

هذه القيود مطبّقة على مستوى **قواعد أمان قاعدة البيانات** (`firestore.rules`) وليس فقط في واجهة
التطبيق، بحيث لا يمكن تجاوزها حتى باستدعاء مباشر لقاعدة البيانات:

- **تسجيل عضو جديد**: يُنشئ المستخدم حسابه بحالة "بانتظار الموافقة" فقط؛ لا يصبح نشطاً إلا بعد
  اعتماد مسؤول النظام من مركز القرارات التنفيذية.
- **إضافة مشروع جديد**: لا يُنشأ أي مشروع مباشرة (`allow create: if false` في القواعد)؛ يُرسل
  "طلب إضافة مشروع" ولا يُنفَّذ إلا عبر Cloud Function بعد اعتماد مسؤول النظام.
- **تعديل الموعد النهائي لمشروع**: حقل `dueDate` محمي صراحة في القواعد من التعديل المباشر؛
  التعديل يمر حصراً عبر "طلب تعديل موعد نهائي" يعتمده مسؤول النظام.

كل هذه الطلبات، بالإضافة إلى "القرارات التنفيذية" العامة المرفوعة من التحديثات اليومية، تظهر في
**مركز القرارات التنفيذية** مرتبة حسب الأولوية وتأثير التأخير.

## الإشعارات (بريد إلكتروني وواتساب)

- عند اعتماد/رفض أي طلب، تُرسل Cloud Function إشعاراً تلقائياً لصاحب الطلب عبر البريد الإلكتروني
  (Gmail SMTP) وواتساب (Twilio WhatsApp API) بحسب بيانات الاتصال المسجّلة له.
- من شاشة "إدارة المستخدمين"، يمكن لمسؤول النظام إرسال رسالة حرة لأي مستخدم عبر البريد أو واتساب
  أو كليهما في أي وقت (زر ✉️ بجانب كل مستخدم).

## أبرز الميزات

- **لوحة قيادة مركزية**: نسبة الإنجاز، التأخير بالأيام، المخاطر، العوائق، القرارات المطلوبة،
  ترتيب الإدارات، ورسوم بيانية تفاعلية (أعمدة ودائرية) — بيانات لحظية (Real-time) من Firestore.
- **صفحات إدارات مستقلة** لكل إدارة مع مؤشراتها ومشاريعها.
- **تحديث يومي مفصل**: إنجازات، مهام منجزة، مخاطر جديدة، عوائق، قرارات مطلوبة، ونسبة تقدم.
- **لوحة مهام لكل مشروع (Kanban)** بأسلوب Jira/Trello: قائمة الانتظار، قيد التنفيذ، قيد المراجعة،
  معلقة، منجزة — مع السحب والإفلات، اسم المنفذ، وقت آخر تحديث، ونسبة الإنجاز.
- **تقارير أسبوعية وشهرية تلقائية** مع ملخص تنفيذي مُولّد، تحليلات، وتعليق نصي يدوي.
- **مركز قرارات تنفيذية موحّد** لكل طلبات الموافقة (تسجيل/مشروع/موعد/قرار)، مرتبة حسب الأولوية
  وتأثير التأخير.
- **سجل تدقيق** كامل لكل العمليات، وإدارة مستخدمين شاملة لمسؤول النظام.
- **مصادقة حقيقية** عبر Firebase Authentication، مع تسجيل ذاتي بانتظار الموافقة، وآلية تعيين أول
  مسؤول نظام تلقائياً عند خلوّ المنصة.

## البنية التقنية

| الطبقة | التقنية |
| --- | --- |
| الواجهة | Flutter (ويب + أندرويد)، Provider لإدارة الحالة |
| المصادقة | Firebase Authentication (بريد إلكتروني/كلمة مرور) |
| قاعدة البيانات | Cloud Firestore (استماع لحظي Real-time) |
| المنطق الخلفي | Cloud Functions (TypeScript) — `functions/` |
| البريد الإلكتروني | Nodemailer عبر Gmail SMTP (قابل للاستبدال بـ SendGrid/Mailgun) |
| واتساب | Twilio WhatsApp API (قابل للاستبدال بـ Meta WhatsApp Cloud API) |
| الاستضافة | Firebase Hosting |

كل عملية اعتماد أو إشعار حساس تمر عبر Cloud Functions باستخدام Admin SDK، ولا تُنفَّذ أبداً من
جهة العميل مباشرة — هذا يضمن أن بوابات الموافقة الثلاث لا يمكن تجاوزها حتى لو تم التلاعب بتطبيق
العميل.

## ربط المنصة بـ Firebase والنشر (دليل خطوة بخطوة)

### 1) إنشاء مشروع Firebase

1. افتح [console.firebase.google.com](https://console.firebase.google.com) وأنشئ مشروعاً جديداً.
2. فعّل **Authentication → Sign-in method → Email/Password**.
3. فعّل **Firestore Database** في وضع **Production mode**.
4. فعّل **Functions** (يتطلب ترقية لخطة **Blaze** — دفع حسب الاستخدام، بحصة مجانية شهرية كبيرة).
5. فعّل **Hosting**.

### 2) تثبيت الأدوات

```bash
npm install -g firebase-tools
dart pub global activate flutterfire_cli
```

### 3) ربط المشروع

من داخل مجلد `gov_executive_platform`:

```bash
firebase login
flutterfire configure --project=<project-id>
```

سيولّد هذا الأمر ملف `lib/firebase_options.dart` الحقيقي (يستبدل النسخة المؤقتة الموجودة حالياً)،
كما يحدّث `.firebaserc` تلقائياً — إن لم يحدث، عدّل `.firebaserc` يدوياً وضع معرّف مشروعك مكان
`REPLACE_WITH_YOUR_FIREBASE_PROJECT_ID`.

### 4) إعداد بريد Gmail

1. فعّل التحقق بخطوتين على حساب Gmail: [myaccount.google.com/security](https://myaccount.google.com/security)
2. أنشئ **App Password** جديدة (كلمة مرور تطبيقات) وانسخ الرمز المكوّن من 16 خانة.

### 5) إعداد Twilio لواتساب

1. أنشئ حساباً في [twilio.com/try-twilio](https://www.twilio.com/try-twilio).
2. انسخ **Account SID** و **Auth Token** من لوحة التحكم.
3. فعّل **WhatsApp Sandbox** (Messaging → Try it out → Send a WhatsApp message) واحصل على رقم
   Twilio التجريبي وكود الانضمام. كل رقم مستلم يجب أن يرسل "join xxxx-xxxx" لمرة واحدة قبل
   استقبال الرسائل (قيد خاص ببيئة Sandbox المجانية فقط).

### 6) تخزين الأسرار (لا تُكتب أبداً داخل الكود)

```bash
cd functions
firebase functions:secrets:set GMAIL_USER
firebase functions:secrets:set GMAIL_APP_PASSWORD
firebase functions:secrets:set TWILIO_ACCOUNT_SID
firebase functions:secrets:set TWILIO_AUTH_TOKEN
firebase functions:secrets:set TWILIO_WHATSAPP_FROM   # مثال: +14155238886
```

### 7) تثبيت اعتماديات الدوال الخلفية

```bash
cd functions
npm install
npm run build   # للتأكد من عدم وجود أخطاء TypeScript قبل النشر
cd ..
```

### 8) النشر

```bash
flutter build web --release
firebase deploy
```

هذا ينشر قواعد Firestore (`firestore.rules`)، الفهارس (`firestore.indexes.json`)، الدوال الخلفية
(`functions/`)، والموقع (`build/web`) دفعة واحدة. ستحصل على رابط مباشر مثل
`https://<project-id>.web.app`.

### 9) تعيين أول مسؤول نظام

1. افتح الرابط المنشور وسجّل حساباً جديداً (Sign up) — سيبقى بحالة "بانتظار الموافقة".
2. بما أن قاعدة البيانات لا تحتوي على أي مسؤول نظام بعد، ستظهر تلقائياً رسالة وزر
   **"تعيين نفسي كأول مسؤول نظام"** على شاشة الانتظار — اضغطه مرة واحدة فقط.
3. من هذه اللحظة فصاعداً، كل تسجيل جديد وكل مشروع وكل تعديل موعد نهائي يحتاج موافقتك من
   **مركز القرارات التنفيذية**.

### التطوير والتعديل لاحقاً

- عدّل شاشات Flutter داخل `lib/` كالمعتاد، وشغّل `flutter run -d chrome` للمعاينة الفورية (بعد
  ربط Firebase في الخطوة 3، حتى في وضع التطوير).
- عدّل منطق الدوال الخلفية داخل `functions/src/`، وشغّل `npm run build` ثم `firebase deploy --only functions`
  لنشر التعديلات فقط دون إعادة نشر كل شيء.
- عدّل صلاحيات قاعدة البيانات في `firestore.rules` ثم `firebase deploy --only firestore:rules`.
