# اختبارات قواعد الأمان

تُشغَّل على **محاكي Firestore** حقيقي، لا محاكاةً في الذاكرة: قواعد الأمان
لغة مستقلة تُنفَّذ على الخادم، وقراءتها بالعين لا تُثبت شيئاً.

```bash
# طرفية أولى
firebase emulators:start --only firestore --project rules-test

# طرفية ثانية
cd test_rules && npm install && npm test
```

## الملفات

- **`membership.rules.test.mjs`** — الكتابة: من يضيف نفسه إلى مشروع وكيف.
- **`feedback.rules.test.mjs`** — الشكاوى والاقتراحات: من يرفع، ومن يقرأ،
  ومن يبتّ؛ وأن المسجِّل لا يزرع لنفسه استثناء صلاحيات ولا استثناءً من
  شرط البريد الوزاري لحظة إنشاء سجله.
- **`scope.rules.test.mjs`** — **نطاق الاستعلام**، وهو موضع أعطال حقيقية:
  قواعد Firestore ترفض ولا تُصفّي، فالمجموعة تُطلب بنطاق يضمن أن كل ما
  تعيده مسموح، وإلا رُفض الطلب كله فتظهر الشاشة فارغة كأن لا بيانات.
  واختبارُ مستندٍ مفرد ينجح بينما الاستعلام الذي يبنيه البرنامج يُرفض —
  فلا يكشف شيئاً. هكذا اختفت مشاريع الموظف وأعماله معاً.

كل حالة رفض في `membership.rules.test.mjs` تمثّل تجاوزاً حقيقياً: موظف يضيف
غيره، أو يزيح زميله عن مشروعه، أو يتسلّل إلى مشروع إدارة أخرى، أو يُمرّر
تعديلاً على الموعد النهائي تحت غطاء الانضمام.

وقد تحقّقنا أن هذه الاختبارات **تعضّ فعلاً**: بإسقاط شرط `legacyManagerConsistent`
من القاعدة سقط اختبار «يضبط الحقل المفرد على غير عضو» وحده — فهي تحرس ما
تدّعي حراسته لا أكثر. وكذلك بإرجاع قراءة المشاريع إلى `canBrowseDeptProjects`
سقطت ثلاثة اختبارات في `scope.rules.test.mjs` وحدها، وبقيت اختبارات الكتابة
الثلاثة عشر ناجحة — أي أن توسيع القراءة لم يفتح كتابةً.
